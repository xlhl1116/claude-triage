## 分类依据

大类的划分参考了三类公开的真实使用研究（2026-09-28 查证）：

| 来源 | 发布时间 | 与本表相关的发现 |
|---|---|---|
| OpenAI / NBER《How People Use ChatGPT》（WP 34255） | 2025-09 | 7 大类、24 细类。实用建议 28.8%、信息查询 24.4%、写作 23.9%、多媒体 7.3%、自我表达 5.3%、技术帮助 5.1%。最大的细类依次是具体信息查询 18.3%、辅导讲解 10.2%、修改点评用户文本 10.0%、操作建议 8.5%、个人写作 8.0% |
| Anthropic Clio（2024-12）与 Economic Index（2025-02 至 2026-06） | 2024-12 至 2026-06 | Claude 上编程占 34–37%（API 上 44–46%），教育 9%→15%，艺术 / 写作 / 媒体约 10%，商业策略约 6%，AI/ML 开发约 6%，DevOps 约 4%，数字营销约 4%，情感类约 2.9%。Claude Code 里 UI 组件开发 12%、Web / 移动应用 8%，调试占编程的约 13% |
| Microsoft《Copilot Usage Report 2025》 | 2025-12 | 30 个话题、11 种意图。排名前列的是科技、工作职场、健康健身、语言翻译；移动端最常见的是“健康 + 搜索” |

结论：
- **软件开发**是 Claude 用户和 Claude Code 的主战场，因此拆得最细（见 §1）。
- **写作、信息查询、实用建议、教育**是通用助手的四大块，各自单列。
- **健康、法律、金融**的使用量不算最大，但出错代价高，设最低配置。

## 图例

- **模型 · 深度**：Haiku 4.5 / Sonnet 5 · low|medium|high / Opus 5.5 · medium|high|max / Fable 5.1 · max
- **工具**：`代码`＝读写文件和执行命令；`只读`＝读文件和搜索代码；`联网`＝网页搜索和抓取；`文件`＝读写文件、不能执行命令；`无`＝只对话
- **最低**：不会被后台下调到这一档以下

## 后台微调（所有大类通用）

| 信号 | 调整 |
|---|---|
| 规模：整个仓库、多个服务、上万行、长文档 | 上调一档 |
| 风险：生产环境、支付或金融、数据迁移、不可回滚、正式对外发布 | 上调一档 |
| 清晰度：需求模糊、“帮我看看怎么做比较好” | 上调一档 |
| 清晰度：给了明确步骤或示例 | 下调一档（不低于“最低”） |
| 输入量：贴了很长的代码、日志或文档 | 上调一档 |
| 要求条目 ≥ 5 条 | 上调一档 |

- 最多上调两档。最顶上的 Fable 5.1 · max 只通过上调才会用到，例如“分布式架构 + 生产环境 + 整个仓库”。
- **模型阶梯**（只在后台使用）：Haiku 4.5 → Sonnet 5 · low → Sonnet 5 · medium → Sonnet 5 · high → Opus 5.5 · medium → Opus 5.5 · high → Opus 5.5 · max → Fable 5.1 · max

## 分类方式

1. **规则引擎**：对细类关键词做初筛，给出候选类别，并检测微调信号。不调用模型。
2. **导诊台**（Haiku 4.5）：对照本表判定细类。规则非常有把握时直接采用规则结果。导诊台有只读权限，可以看一眼文件列表、搜关键词来判断改动范围（待确认）。
3. **查表**：类别确定后，模型和思考深度严格查表并叠加微调，保证可解释、可复现。
4. **执行 agent 按“模型 × 深度 × 工具”组合生成**，按本表约十几个，不是每个细类一个。细类的专属指令由导诊台派单时附上。
